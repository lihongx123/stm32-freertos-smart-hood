# STM32F103 FreeRTOS smart hood simulation

STM32F103C8Tx/Cortex-M3 firmware based on the existing CubeMX project, run in Renode. All smoke, temperature, humidity, light and differential-pressure values are generated by Python. Fan and lamp outputs are logical states reported over UART; no physical hardware validation was performed.

## Key features

- FreeRTOS with the CMSIS-RTOS2 API and five tasks: CommTask, SensorTask,
  ControlTask, FaultTask and MonitorTask.
- USART RX interrupt -> ring buffer -> direct task notification, plus typed
  queues, mutex-protected shared snapshots and `vTaskDelayUntil()` scheduling.
- INIT/NORMAL/WARNING/FAULT/RECOVERY state handling with deterministic fault
  injection and Python + Renode scenario automation.

## Architecture

```text
Python virtual scenarios -> Renode USART1 RX IRQ
  -> fixed ring -> direct task notification -> CommTask
  -> mutex-protected SensorData -> periodic SensorTask
  -> typed four-item queue -> ControlTask -> fan/lamp/system states
                            FaultTask -> timeout/invalid/queue/health faults
                          MonitorTask -> task heartbeats, software watchdog, metrics
```

- CommTask: bounded CSV parsing outside the ISR. The 256-byte ring holds 255 bytes; full ring rejects incoming bytes and increments overflow. Corrupted/oversized input is discarded to a newline. No ISR allocation, parsing or logging.
- SensorTask: `vTaskDelayUntil()` at 100 ms, publishes typed snapshots without blocking on a full queue.
- ControlTask: separate `FanMode` and `SystemState`; reports state changes, never claims a real motor output.
- FaultTask: 100 ms checks for stale sensors, invalid frames, communication silence, queue overflow and task-health faults.
- MonitorTask: uses the generated default task; checks heartbeats every 250 ms, detects 1500 ms logical stalls, logs once per second. This is a software monitor, not an independent hardware watchdog.
- One mutex protects shared runtime snapshots; a second serializes task UART TX. ISR uses neither mutex.
- Periodic tasks implement timeouts and health checks directly. No additional application software timer is needed; the generated FreeRTOS timer service remains configured but is not a claimed application feature.

## Protocol and state machine

USART1: 115200, 8N1. Frame: `S,smoke,temp,hum,light,dp\n`.
Accepted integer ranges: smoke/light 0..1000, temperature -40..125, humidity 0..100, pressure -1000..1000. These are simulation values, not calibrated sensor readings. Max frame buffer: 96 bytes. Fragmentation, consecutive frames, malformed values, embedded NUL and oversized frames are tested.

Thresholds live in `Core/Inc/app_config.h`: smoke 100/300/600/850 selects LOW/MEDIUM/HIGH/BOOST (below 100 OFF); pressure <= -10 forces BOOST/WARNING; light < 30 enables the logical lamp.

INIT -> NORMAL/WARNING; faults -> FAULT/BOOST. Valid input and cleared fault flags lead through RECOVERY for ten subsequent control cycles before NORMAL/WARNING. Invalid input resets recovery. Input timeout is 2000 ms; queue-fault hold is 2000 ms.

Fault mask bits: 1 sensor timeout, 2 invalid frame, 4 communication timeout, 8 queue overflow, 16 task-health failure. Health bits identify Comm/Sensor/Control/Fault as bits 0..3.

Simulation-only injection is explicitly enabled by `APP_SIMULATION_TEST_HOOKS`: `T,task_index,milliseconds\n` pauses the selected logical task (0..3, max 5000 ms). It is used to exercise real RX overflow and watchdog logic. Disable this option before any production adaptation.

## Build and validation

In Ubuntu/WSL, from this directory:

```sh
make -j$(nproc)
arm-none-eabi-size build/SensorTelemetry.elf
python3 tests/run_scenarios.py --output results/my-new-run
python3 tools/summarize.py results/my-new-run
```

The runner uses `renode` on PATH, otherwise `$HOME/tools/renode/renode`; override with `--renode /path/to/renode`. Output directory must not already exist. Local TCP ports 12345/12346 must be free. Python uses only the standard library. Renode is launched headlessly and stopped on completion/failure; pass/fail comes from captured UART output, not Renode's process exit code alone.

Optional host unit checks:

```sh
gcc -std=c11 -Wall -Wextra -Werror -ICore/Inc tests/unit.c Core/Src/uart_ring.c Core/Src/hood_state.c -o build/host-unit
build/host-unit
```

`renode/hood.resc` reuses the installed STM32F103 platform, with SysTick and TIM1 frequencies adjusted to the firmware's 8 MHz HSI clock. Default model SysTick is 72 MHz and cannot be used unchanged for timeout measurements. First platform load may download its referenced SVD. No vendor source or CubeMX regeneration was required.

## Measured validation

Final evidence: `results/scenarios-final/` (transmitted frames, source/ELF fingerprints, size and JSON summaries). Generated firmware binaries and raw logs remain local.

- Build PASS. Renode 1.17.0 boot, scheduler and repeating task execution PASS.
- **19/19 scenario assertions PASS**, 43.7 simulated seconds; idle/cooking/backflow/dark/invalid/recovery, silence timeout, fragments/bursts, malformed/NUL/oversized input, ring overflow, stalled ControlTask and queue overflow.
- Host ring FIFO/full/empty/wraparound and control thresholds/recovery tests PASS (`results/unit-test.log`).
- Final size: text **27576 B**, data **108 B**, bss **18164 B**. Linker retains 64 KiB FLASH / 20 KiB RAM limits. Baseline: 12424/16/8200 B.
- Minimum observed FreeRTOS free heap: **4168 B** of configured 12288 B.
- Minimum observed free stack words (32-bit): Comm **106**, Sensor **220**, Control **204**, Fault **92**, Monitor **310**. These are test high-water marks, not proofs of worst-case stack safety.
- Last periodic snapshot: UART bytes **4391**, valid frames **175**, frame errors **14**, ring-overflow bytes **770**, queue drops **17**, state transitions **24**, fault entries **7**; final state NORMAL, fault mask 0.

Errors/overflows in this run are **deliberate fault injections**, not a normal-operation reliability rate. Counters are the last periodic snapshot, not an invented exact shutdown total. Earlier two runs and all initial failure logs remain under `results/`. The initial `make -B` evidence attempt hit an existing-build-directory error; clean rebuild passed. Initial Renode file-backend path and clock mismatch were corrected before scenario testing.

Renode logs also contain disabled-DMA-channel request warnings from the installed timer/DMA model wiring. They were not hidden; actual UART/task assertions passed despite those warnings.

## Limits

No physical STM32 board, MQ2/DHT11/pressure sensors, fan motor, electrical timing or hardware watchdog was tested. Host-injected UART traffic does not validate real baud-rate error handling. Renode's platform is broader than the physical C8 memory map; the linker enforces image limits, not full hardware memory-fault equivalence. Software monitoring reports stalled tasks but cannot reset a hung CPU; a stalled ControlTask cannot change outputs until it resumes. No 30-minute or longer stability claim is made. Thresholds and fault actions are illustrative, not a safety-certified appliance policy.

Existing ST/FreeRTOS provenance and license headers remain intact. The application and host test additions do not change ownership of generated/vendor code. The supplied directory was not a Git repository.
